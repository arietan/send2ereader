How it works

Three steps. Zero setup.

01

Drop a file

Any EPUB, MOBI, AZW3, PDF, or comic up to 200 MB, dropped straight from your phone or laptop browser into Vercel Blob.

02

Get a code

A four-character code from a 28-letter alphabet that skips look-alikes (no 0/O, no 1/I). A QR shows up next to it.

03

Type it on your ereader

Open the built-in browser, go to b2k.vercel.app, type the code. The book lands in your library.

Privacy by default

The file is gone in an hour.
Or sooner.

Browser uploads go straight to Vercel Blob — our backend mints a code and forgets. A daily sweep deletes anything older than an hour. The receiver can claim once, then release. No accounts. No logs. No analytics.

  • Direct browser → blob upload

    Files never pass through our serverless functions.

  • One-hour TTL, hard cap

    Cron sweeps the bucket. Nothing lingers.

  • Released after claim

    Sender can wipe it the moment the ereader downloads.

  • Read the source

    Six route handlers. ~600 lines. MIT.

One Vercel project, one Blob store. Live in three minutes — Hobby plan covers the typical home use case for free.

Deploy to Vercel Read the README
~/send2ereader 
# clone the fork
git clone https://github.com/arietan/send2ereader
cd send2ereader

# local dev (needs a Vercel Blob token)
npm install
npx vercel link && npx vercel env pull .env.local
npm run dev▌

Or click Deploy to Vercel — it forks the repo, provisions a Blob store, and runs the build for you.
